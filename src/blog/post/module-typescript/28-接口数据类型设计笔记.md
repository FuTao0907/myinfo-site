<small>以后写接口类型，尽量按这套统一结构来，不要每个页面都自己重新想。</small>

# 一、统一响应结构

```ts
type ApiResponse<T> = {
  code: number
  message: string
  data: T
}
```

- 原理总结：把响应公共层抽出来，内部数据再用泛型传入。
- 注意点：统一结构后，前端封装请求层会更简单。

# 二、分页列表

```ts
type PageParams = {
  page: number
  pageSize: number
}

type PageResult<T> = {
  list: T[]
  total: number
  page: number
  pageSize: number
}
```

- 原理总结：分页参数和分页结果分别抽象，任何列表接口都能复用。
- 注意点：参数命名一旦定了就全项目统一。

# 三、表单类型

```ts
type UserForm = {
  name: string
  email: string
  roleIds: number[]
}
```

- 原理总结：表单类型要贴近提交结构，而不是盲目照抄详情结构。
- 注意点：新增、编辑、详情经常不是同一个类型。

# 四、树形与选项字典

```ts
type TreeNode<T = unknown> = {
  id: number | string
  label: string
  children?: TreeNode<T>[]
  extra?: T
}

type OptionItem = {
  label: string
  value: string | number
}
```

- 原理总结：树形和字典是后台系统里最常重复出现的两类结构。
- 注意点：不要每个页面自己起一套字段名，尽量统一成 `label/value` 或 `id/label`。

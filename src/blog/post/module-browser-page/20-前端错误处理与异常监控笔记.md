# 一、同步与异步兜底

```ts
/**
 * 包装同步函数，统一捕获异常。
 */
function safeRun(fn: () => void) {
  try {
    fn()
  } catch (error) {
    console.error(error)
  }
}

/**
 * 包装异步函数，统一捕获异常。
 */
async function safeRunAsync<T>(fn: () => Promise<T>) {
  try {
    return await fn()
  } catch (error) {
    console.error(error)
    throw error
  }
}
```

- 原理总结：同步错误靠 `try/catch`，异步错误靠 `await + try/catch`。
- 注意点：异步包装后如果还要上层处理，别把异常吞掉。

# 二、全局错误监听

```ts
/**
 * 监听运行时错误。
 */
function listenWindowError() {
  window.addEventListener('error', (event) => {
    console.error('window error:', event.message)
  })
}

/**
 * 监听未处理的 Promise 异常。
 */
function listenUnhandledRejection() {
  window.addEventListener('unhandledrejection', (event) => {
    console.error('unhandled rejection:', event.reason)
  })
}
```

- 原理总结：局部漏掉的异常最终会冒到全局事件里。
- 注意点：全局监听是兜底，不代表局部错误处理就可以不写。

# 三、资源加载失败

```ts
/**
 * 监听图片、脚本、样式等资源加载失败。
 */
function listenResourceError() {
  window.addEventListener(
    'error',
    (event) => {
      const target = event.target as HTMLElement | null
      if (target) console.error('resource load failed:', target)
    },
    true
  )
}
```

- 原理总结：资源错误不会像普通运行时异常那样自动进入统一逻辑，需要单独监听。
- 注意点：第三个参数用捕获阶段更容易拿到资源加载失败。

# 四、错误上报

```ts
/**
 * 上报错误日志到服务端。
 */
async function reportError(payload: Record<string, unknown>) {
  await fetch('/api/log', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload),
  })
}
```

- 原理总结：把错误信息转成结构化数据统一上报，方便后端归档和检索。
- 注意点：上报逻辑自己也要做失败兜底，别让它反过来制造新异常。

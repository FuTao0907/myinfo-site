# 一、基础校验

```ts
/**
 * 校验邮箱格式。
 */
function isEmail(value: string) {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
}

/**
 * 校验必填项。
 */
function isRequired(value: string) {
  return value.trim().length > 0
}
```

- 原理总结：基础校验优先本地快速拦截，减少无意义请求。
- 注意点：复杂规则最终仍要服务端再校验一次。

# 二、提交防重复

```ts
/**
 * 包装提交函数，防止重复点击。
 */
function createSubmitLock<T extends (...args: unknown[]) => Promise<unknown>>(fn: T) {
  let loading = false

  return async (...args: Parameters<T>) => {
    if (loading) return
    loading = true

    try {
      return await fn(...args)
    } finally {
      loading = false
    }
  }
}
```

- 原理总结：在请求期间加锁，直到本次提交结束才允许下一次点击。
- 注意点：防重复提交比单纯按钮置灰更稳。

# 三、草稿保存

```ts
/**
 * 保存表单草稿。
 */
function saveDraft<T>(key: string, data: T) {
  localStorage.setItem(key, JSON.stringify(data))
}

/**
 * 读取表单草稿。
 */
function loadDraft<T>(key: string): T | null {
  const raw = localStorage.getItem(key)
  return raw ? (JSON.parse(raw) as T) : null
}
```

- 原理总结：利用本地存储保存未提交内容，避免刷新或误关页面丢数据。
- 注意点：草稿里不要存敏感信息。

# 四、错误映射

```ts
/**
 * 把字段错误列表转成对象结构。
 */
function mapErrors(list: Array<{ field: string; message: string }>) {
  return list.reduce<Record<string, string>>((acc, item) => {
    acc[item.field] = item.message
    return acc
  }, {})
}
```

- 原理总结：把后端返回的错误数组转成前端更容易渲染的键值结构。
- 注意点：字段名必须和表单模型一致，不然提示挂不到对应输入框上。

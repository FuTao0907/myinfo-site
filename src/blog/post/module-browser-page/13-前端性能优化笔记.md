# 三、图片优化模板

```html
<img
  src="/images/card-640.webp"
  width="320"
  height="180"
  loading="lazy"
  decoding="async"
  alt="card cover"
/>
```

- 原理总结：同时处理图片体积、加载时机和布局占位。
- 注意点：图片最大问题通常不是格式，而是原图尺寸远大于实际展示尺寸。

# 四、动态导入

```ts
/**
 * 用到时再加载重模块。
 */
async function loadModule() {
  // import() 会把模块拆成单独资源，直到调用时才下载。
  const mod = await import('./heavy-module.js')
  return mod
}
```

- 原理总结：把大模块从首屏主包里拆出去。
- 注意点：核心首屏逻辑不要拆得过碎。

# 五、批量 DOM 与长列表

```ts
/**
 * 使用 DocumentFragment 批量插入节点。
 */
function appendItems(container: HTMLElement, items: string[]) {
  const fragment = document.createDocumentFragment()

  items.forEach((text) => {
    const li = document.createElement('li')
    li.textContent = text
    fragment.appendChild(li)
  })

  // 一次性挂载，减少多次回流和重绘。
  container.appendChild(fragment)
}
```

- 原理总结：节点先在内存中拼装，最后一次性插入真实 DOM。
- 注意点：超长列表更适合配合虚拟列表，而不是一次全渲染。

# 六、Web Worker

```ts
/**
 * 主线程启动 Worker 处理重计算。
 */
const worker = new Worker('/worker.js')
worker.postMessage([1, 2, 3, 4, 5])
worker.onmessage = (event) => {
  console.log('worker result:', event.data)
}
```

- 原理总结：把重 CPU 计算移出主线程，减少交互卡顿。
- 注意点：Worker 不能直接操作 DOM。

# 七、渲染阶段优化

- 动画优先改 `transform` 和 `opacity`。
- 滚动监听优先用 `passive`。
- 可视区判断优先用 `IntersectionObserver`。
- 动画循环优先用 `requestAnimationFrame`。

- 原理总结：性能优化的重点不是“多写技巧”，而是减少主线程阻塞和无意义渲染。
- 注意点：这篇只讲性能方法本身，不再重复异步控制和工具函数。

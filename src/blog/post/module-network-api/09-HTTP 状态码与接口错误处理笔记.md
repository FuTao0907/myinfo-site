# 一、最常用状态码速查

| 状态码 | 含义 |
| --- | --- |
| 200 | 请求成功 |
| 201 | 创建成功 |
| 204 | 成功但无响应体 |
| 400 | 请求参数有问题 |
| 401 | 未认证 |
| 403 | 已认证但无权限 |
| 404 | 资源不存在 |
| 409 | 资源冲突 |
| 422 | 参数格式对但业务校验失败 |
| 500 | 服务端异常 |

# 二、错误分层

- 网络层错误：断网、超时、DNS 失败。
- 协议层错误：`404`、`500`、`502` 这类 HTTP 状态异常。
- 业务层错误：库存不足、用户名重复这类业务失败。
- 解析层错误：前端按错格式解析响应。

# 三、统一错误结构

```json
{
  "code": 10001,
  "message": "参数校验失败",
  "data": null
}
```

- 原理总结：HTTP 状态码表达大类语义，业务码表达细节。
- 注意点：不要把所有错误都硬塞成 `200`。

# 四、前端处理顺序

1. 先判断有没有拿到响应。
2. 再看 HTTP 状态码。
3. 再看业务码和 message。
4. 最后决定是否重试、提示、跳登录或降级处理。

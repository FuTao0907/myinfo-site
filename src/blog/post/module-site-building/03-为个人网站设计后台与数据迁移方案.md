# 为什么个人网站也需要后台

很多时候一开始做个人网站，都会觉得：

“我自己改文件不就行了吗？”

这个想法在最初完全没问题，但当网站功能慢慢变多之后，就会发现后台不是为了“看起来专业”，而是为了把维护成本降下来。

比如后面我希望能方便地：

- 新增文章
- 编辑日常
- 改项目列表
- 改个人资料
- 改社交链接
- 控制哪些内容展示，哪些内容先不公开

如果这些都继续手改代码和常量文件，迟早会越来越不顺。

# 当前项目的数据现状

现在这个项目里，数据来源大概分成两部分：

## 1. 本地 Markdown

负责：

- 技术文章
- 日常记录

这是当前的内容源。

## 2. 本地常量配置

负责：

- 站点资料
- 项目列表
- 首页布局配置
- 社交链接

这类数据目前都还写在前端项目里。

这种方式的优点是简单，但问题也很明显：

- 不方便维护
- 不适合后台管理
- 不利于正式上线后的长期运营

# 为什么要把 MySQL 引进来

如果后面只是多写几篇文章，其实本地 Markdown 也能继续用。

但如果想把整个网站真正变成一个可以持续维护的站点，那数据库几乎是绕不开的。

## 1. 结构化数据更适合数据库

比如这些内容，本质上都很适合数据库：

- 文章
- 标签
- 项目
- 站点资料
- 社交链接

它们都需要：

- 查询
- 排序
- 筛选
- 更新

这正是数据库擅长的事情。

## 2. 后台管理天然依赖数据库

后台最核心的价值是“改数据”。

一旦开始有下面这些需求：

- 草稿
- 发布
- 推荐
- 排序
- 操作日志

数据库就会比文件系统更自然。

## 3. 前后端边界更清楚

当前项目以后比较合理的职责划分应该是：

- Next.js：前台展示
- NestJS：接口和业务逻辑
- MySQL：存储结构化内容

这样每一层都更清楚。

# 推荐的整体结构

我更倾向于把整个系统拆成三部分：

## 1. 前台网站

继续用当前这个 Next.js 项目，负责：

- 首页展示
- 文章列表与详情
- 日常列表与详情
- 项目页
- 一些主题和动效交互

## 2. 后端接口

使用 NestJS，负责：

- 文章接口
- 项目接口
- 站点配置接口
- 后台管理接口
- 导入和校验逻辑

## 3. 后台管理端

单独做一个后台项目，负责：

- 内容管理
- 配置管理
- 导入管理
- 权限管理

这三者的链路应该是：

`后台 -> NestJS -> MySQL -> 前台`

# 后台到底要管什么

我希望这个后台不是“文章后台”，而是“整个网站后台”。

也就是说，它应该覆盖下面这些内容。

## 1. 文章与日常

这部分是最核心的内容：

- 新增
- 编辑
- 删除
- 草稿
- 发布
- 标签管理

## 2. 项目管理

项目页现在其实也很重要，因为它更像是整个站点的作品展示区。

后台里最好能直接维护：

- 项目名称
- 描述
- 封面图
- Demo 地址
- 仓库地址
- 排序
- 是否推荐

## 3. 站点资料

站点中还有一批很明显的个人信息类配置：

- 标题
- 简介
- 关键词
- 邮箱
- 简历地址
- 社交链接
- 地图位置

这类内容如果以后都放后台改，会比改前端常量舒服很多。

## 4. 首页配置

这一块不是第一优先级，但很值得预留。

比如以后我可能希望后台可以配置：

- 首页卡片是否显示
- 首页卡片顺序
- 首页推荐内容
- 顶部导航项

如果提前把这个方向想清楚，后面首页就不会只能靠手改代码了。

# Markdown 在未来还要不要保留

我觉得要保留，但角色要变化。

不是继续让前台直接读它，而是把它变成：

**导入源**

也就是说：

- 平时本地还是可以写 Markdown
- 后台支持导入 Markdown
- 导入器解析后写入 MySQL
- 前台和后台最终都只认数据库

这条链路会更稳：

`Markdown -> 导入器 -> MySQL -> NestJS -> Next.js`

# 这次最重要的一个认知

我觉得做这种个人网站，最容易忽略的一点是：

前端页面其实只是最外层。

真正决定后面能不能持续做下去的，是下面这些东西有没有提前想清楚：

- 数据从哪里来
- 内容怎么更新
- 谁负责展示
- 谁负责管理
- 谁才是最终真源

如果这些边界不清楚，项目写到后面就会越来越乱。

# 后面准备怎么落地

按现在这个项目的状态，我更倾向于分阶段推进。

## 第一阶段

先把前台站点整理稳定：

- 替换成自己的资料
- 把文章和日常继续补起来
- 把项目列表梳理干净

## 第二阶段

开始搭 NestJS 和 MySQL：

- 设计表结构
- 实现文章和项目接口
- 实现站点配置接口

## 第三阶段

做后台管理端第一版：

- 登录
- 文章管理
- 项目管理
- 站点设置
- Markdown 导入

## 第四阶段

再扩展更舒服的能力：

- 上传资源
- 导入记录
- 操作日志
- 首页配置管理

# 结尾

以前我更容易把个人网站看成一个展示页面，现在慢慢会把它看成一个完整的小系统。

而一旦把它当成系统去看，后台、数据库和接口这些东西就不再是“多余的复杂度”，而是让项目长期可维护的基础设施。

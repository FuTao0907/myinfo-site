# 为什么要重构

最开始参考别人的项目搭个人站时，确实能很快看到结果，但后面继续改的时候就会越来越明显地感受到几个问题：

- 目录结构不够清晰
- 组件职责比较混乱
- 有些配置和内容耦合在一起
- 还保留了不少别人的信息和历史残留文件

如果只是本地自己玩，问题不算太大。但一旦准备继续写文章、补项目、做后台，甚至后面正式部署上线，这些问题都会放大。

所以这次整理的目标很明确，不是单纯改样式，而是把项目的结构先定下来。

# 为什么选 Next.js 16

这次项目最终落在 Next.js 16 上，主要是因为它比较符合个人内容站点的使用场景。

## 1. App Router 更适合内容型项目

现在页面的主要结构都在 `src/app` 下，路由更集中，页面组织方式也更直接。

像首页、文章页、日常页、项目页这种结构，在 App Router 下会更容易统一管理。

## 2. Server Component 更适合内容展示

个人站点的很多页面本质上是内容展示页，不一定需要大量客户端状态。

所以把树的顶部尽量放在服务端，是一个比较自然的选择：

- 页面初始渲染更直接
- 不需要额外包装很多客户端外壳
- 后面切到接口取数时，也更容易直接在服务端拉数据

## 3. 后续接 NestJS 和 MySQL 更顺

当前本地文章还是 Markdown，但后面准备逐步切到：

`NestJS + MySQL + 后台管理`

Next.js 在这个链路里更适合做前台展示层，未来只负责：

- 页面渲染
- 路由组织
- 内容展示
- 少量交互逻辑

# 这次主要整理了什么

## 1. 调整项目目录结构

这次主要把目录按职责重新整理了一轮：

- `src/app` 放路由页面
- `src/components/features` 放业务组件
- `src/components/layouts` 放布局相关
- `src/lib` 放常量、内容处理和后续接口层
- `src/styles` 放全局样式

这样后面再看代码时，心里会更有数。

## 2. 把首页的卡片布局单独抽清楚

首页现在最有特点的部分其实是 Bento 卡片区。

这部分如果布局数据、组件映射和样式逻辑混在一起，后面改位置会非常痛苦。

所以现在至少先把：

- 卡片组件
- 卡片布局配置
- 页面承载容器

分开了。

这一步看起来简单，但对后面继续改首页很重要。

## 3. 统一内容来源

当前项目的文章和日常，都是从本地 Markdown 中读取。

这一点虽然以后会逐步切到接口，但在这个阶段还是很有价值：

- 写作成本低
- 内容结构清晰
- 能先把前台渲染流程跑顺

等后面后台准备好了，再把“本地 Markdown”升级成“导入源”。

# 这次重构里比较重要的几个点

## 1. 先把结构稳定下来，再继续补功能

很多时候最容易掉进去的坑，是一边堆功能，一边随手补结构。

短时间看起来很快，但项目一旦继续往下做，就会越来越乱。

这次更像是在做一件基础工作：

先把架子搭稳，再决定后面往哪里长。

## 2. 内容站点的核心是“可持续维护”

个人网站跟一次性活动页不一样。

它最重要的不是某一个页面有多花哨，而是：

- 过几个月回来看还能不能继续写
- 过半年想加新模块时会不会很难下手
- 真正上线后想维护，会不会一改就牵一大片

如果从这个角度看，这次重构反而是很值得的。

## 3. 先允许自己“第一版不完美”

这次整理之后，项目离最终想要的状态还有距离。

比如：

- 站点信息还需要完全替换成自己的
- 项目列表还需要重新整理
- 后台管理还没有落地
- 数据库和接口还在规划中

但只要骨架已经定下来，后面每一步都比之前更明确。

# 后面还准备继续做什么

接下来大概会继续往这几个方向推进：

- 把站点中的他人信息全部替换成自己的资料
- 补全项目页内容
- 继续写技术文章和日常记录
- 设计 NestJS + MySQL 的数据结构
- 做一个整站后台来统一管理内容

# 结尾

这次把个人网站整理成 Next.js 16 项目，对我来说更像是一次“重新开工”。

它不只是把原来的东西迁过来，而是开始认真考虑：

这个站点后面到底要怎么长期做下去。

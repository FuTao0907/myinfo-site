# Myinfo Site 整站后台管理系统设计

## 1. 目标

这个后台不是只管理文章和日常，而是作为整个网站的统一管理入口，后续用于管理：

- 文章
- 日常
- 项目
- 站点资料
- 社交链接
- 首页配置
- 资源文件
- 用户与权限

目标是让你以后尽量不再手改前端代码里的常量和本地 Markdown，而是通过后台完成大多数内容维护。

## 2. 推荐整体架构

建议拆成三个独立部分：

- 前台网站：当前 `Next.js` 项目，负责访客访问
- 后端接口：`NestJS + MySQL`，负责数据与业务逻辑
- 后台系统：单独的管理端项目，负责内容维护

推荐链路：

`后台管理端 -> NestJS API -> MySQL -> 前台网站`

## 3. 推荐项目划分

建议按下面的仓库或目录划分：

- `myinfo-site`：前台站点
- `myinfo-api`：NestJS 接口服务
- `myinfo-admin`：后台管理端

如果前期想降低复杂度，也可以把后台管理端先做进当前前台项目中，使用 `/admin` 路由承载。

但从长期维护角度，更推荐单独项目：

- 前台和后台职责更清晰
- 部署更灵活
- 权限边界更明确
- 后续改版互不影响

## 4. 后台的管理范围

- 技术文章

### 4.3 社交平台管理

- 其他后续新增社交链接

### 4.4 首页配置管理

后台可选管理：

- 首页导航项

- 首页卡片排序
- 项目页推荐项
- 文章页推荐项

### 4.5 资源管理

- 上传文章封面

- 上传头像

推荐资源最终存到对象存储或 CDN，不直接存进数据库。

## 7. 后台权限设计

第一版建议先做最简单的角色模型：

- `super_admin`
- `editor`

权限建议：

- `super_admin`：拥有全部权限
- `editor`：可管理文章、项目和站点资料，但不能管理账号和系统配置

如果一开始只有你一个人用，也建议先把角色模型留好，后续扩展不需要重做。

## 9. Markdown 导入在后台中的位置

你想要的“通过导入方式添加内容”，最适合放在文章管理模块中。

建议支持两种模式：

- 新建文章时直接上传 Markdown
- 在导入中心批量导入 Markdown

建议流程：

1. 上传 Markdown
2. 解析 frontmatter
3. 校验字段
4. 预览内容
5. 选择是“新增”还是“覆盖已有文章”
6. 确认导入

推荐导入后的行为：

- 如果 `slug` 不存在，则新增
- 如果 `slug` 已存在，则提示覆盖更新
- 如果正文为空或格式错误，则拒绝导入

## 10. 后台与 NestJS 的接口边界

后台不应直接操作数据库，而应全部通过 NestJS。

推荐接口分组：

- `/api/admin/auth/*`
- `/api/admin/posts/*`
- `/api/admin/projects/*`
- `/api/admin/site/*`
- `/api/admin/social-links/*`
- `/api/admin/imports/*`
- `/api/admin/uploads/*`

示例接口：

- `POST /api/admin/auth/login`
- `GET /api/admin/posts`
- `POST /api/admin/posts/import-markdown`
- `POST /api/admin/posts/import-preview`
- `PUT /api/admin/posts/:id`
- `DELETE /api/admin/posts/:id`
- `GET /api/admin/projects`
- `PUT /api/admin/site/profile`

## 13. 技术选型建议

后台管理端推荐继续用 `Next.js + TypeScript`，原因：

- 你当前前台已经在用 Next.js
- 组件生态成熟
- 容易共享类型定义
- 后续做登录态和服务端渲染也方便

UI 方案建议：

- 简洁方案：Tailwind CSS + 自定义组件
- 管理系统方案：Ant Design

如果你希望开发效率更高，后台管理端用 Ant Design 会更快。

## 14. 推荐实施顺序

建议按下面顺序推进。

1. 先完成 MySQL 表结构和 NestJS 内容接口
2. 再完成后台登录和基础框架
3. 先做文章管理和 Markdown 导入
4. 再做项目管理和站点设置
5. 最后再扩展首页配置、资源管理和审计日志

## 15. 最终建议

对于你这个网站，最合适的后台定位是：

- 不是单纯博客后台
- 而是整站内容运营后台

第一版建议先管住三大类内容：

- 文章与日常
- 项目
- 站点资料

等这三类跑顺以后，再逐步接管：

- 社交链接
- 首页配置
- 导航配置
- 资源管理

这样不会一开始做得太重，但架构方向是对的。
